Case Brief

I designed and implemented a secure network for a fictional company.

DesX Zolutions Ltd., a fast-growing architectural design firm that moved into a new office with ~160 employees/hosts. The company is expanding its digital operations and needed a structured, segmented network that supports operational efficiency and data protection.

Department Requirements (Summary)

  • Design (55 hosts): Uses CAD/3D tools and cloud collaboration. Internet access plus Project Management; no access to HR, Finance, or IT.
  • Project Management (40 hosts): Scheduling, resourcing, and client communication. Internet access plus Design and Finance; no access to HR or IT.
  • HR (25 hosts): Recruitment and employee records. Internet access only; no access to other departments.
  • Finance (30 hosts): Payroll, budgeting, invoicing, and reporting. Internet access plus Project Management; no access to HR, IT, or Design.
  • IT (10 hosts): Maintains infrastructure and endpoints. Full access to all departments and servers.

Shared Services and Access

  • Web Server: Company website and internal web apps; accessible by all departments.
  • DHCP Server: IP assignment for all subnets.
  • Email Server: Internal and external communications for all departments.
  • Conference Room: Shared video conferencing system for all departments.

Solution Outline

To present my solution and rationale, I structured the work into four phases:

  1. Phase 1: Network Design and Planning
    Requirements analysis, zone-of-trust segmentation, IP addressing with VLSM, topology selection, and justification.
  2. Phase 2: Network Implementation and Configuration
    Device configuration, routing, DHCP, server services, wireless access, and simulated internet connectivity.
  3. Phase 3: Security Controls and Access Policies
    AAA, ZPF, ACLs, and verification of allowed/blocked traffic.
  4. Phase 4: Critical Reflection and Evaluation
    Security posture review, scalability, future-proofing, and implementation challenges.

Phase 1: Network Design and Planning

Overview of Organisation

DesX Zolution is a rapidly growing architectural firm with approximately 160 employees, divided into five different departments. These departments are Design, Project Management, Finance, Human Resources (HR), and IT. Each department has a different role, which performs different business functions with different access network requirements for the departments within the company. To support these network requirements, a proper, secure and scalable network was designed using Cisco Packet Tracer, which focuses on confidentiality and proper utilisation of IP with the help of Variable Length Subnet Masking, which is also called VLSM.

Design Objectives

  • Proper connectivity for all 160 hosts
  • Segment each department to isolate traffic and improve security
  • Ensure inter-department communication aligns with company policy
  • Support dedicated servers (DHCP, Web, Email)
  • Provide internet access via an external network
  • Allow future expansion for users and servers

Zone of Trust Model

To enhance the security and segmentation of the network, the design which is implemented follows the zone of trust model. Based on the network design, each zone represents a different trust level, which controls which information and packets flow in different departments and servers.

Zone Clients Trust Level Access Policy
External ISP / Internet Low Untrusted network; traffic filtered at the router
DMZ Web, Email, DHCP server Medium Accessible to internal users for services
Internal - Business Design, Project Management, Finance High Subnets isolated to prevent unauthorized access
Restricted Zone HR High Fully isolated from other business departments
Administrative IT Very High Trusted IT zone for management and AAA
Shared Access Zone Conference Room Medium Shared access for all departments

Physical Network Design

I designed a hierarchical star architecture with three layers (core, distribution, access) to improve scalability, segmentation, and management. At the core layer, I used a Layer 3 switch as the central distribution device to maintain VLANs and forward traffic. I connected the core router to the ISP router and used it for inter-VLAN routing, DHCP relay, and security controls (ZPF and ACLs).

Network Topology

I used a hierarchical star topology in Cisco Packet Tracer with two routers, one Layer 3 switch, and seven Layer 2 switches. I configured the first router as the simulated ISP (external network). I configured the core router to serve as the main internet gateway and firewall, and connected it directly to the ISP router. I trunked the Layer 3 switch to the core router to distribute traffic to each Layer 2 switch. I connected each Layer 2 switch to end hosts and servers within its subnet.

Justification of using the network topology

Topology Selection

I chose a two-tier design instead of a three-tier model to reduce complexity and cost. With fewer than 200 hosts, this topology provides strong performance and manageable operations.

Star Topology Selection

This star arrangement allows me to add new departments by connecting additional access switches to the core, while keeping routing and security policies centralized.

Segmentation Strategy

I achieved segmentation using IP-based subnetting with VLSM. Each department operates in its own subnet and is connected to the dedicated layer 2 switch of that department, which helps in physical and logical isolation. This also helps in reducing broadcast traffic and simplifying troubleshooting.

Security Implementation

I used a defense-in-depth model that combines the Zone-Based Policy Firewall (ZPF) and Access Control Lists (ACLs) I configured the core router to enforce ZPF rules, which allow only required services such as HTTP, DNS and ICMP. I also implemented ACLs on the core router, which provide additional granular filtering inside the LAN Network I configured AAA (Authentication, Authorisation, and Accounting) on each device, which secures administrative login and records configuration.

Security And Functional Benefits

This design allows efficient performance due to the inter-subnet routing and reduced broadcast traffic; it also ensures scalability by allowing expansion of the network with new subnets. It provides multi-layer security with the help of ZPF, ACLs and AAA and maintains compliance by isolating each department in accordance with the GDPR and Financial Data Protection Act.

Phase 3: Security Controls and Access Policies

Zone-Based Policy Firewall (ZPF)

I configured a Zone-Based Policy Firewall on the core router to inspect and enforce security policies. I grouped all internal VLANs into one internal zone and the ISP into an external zone. Phase 4: Critical Reflection and Evaluation

Security Evaluation

I evaluated the design against confidentiality, integrity, and availability goals for a ~160-host organization. The result is a layered, segmented network with enforced access controls and authenticated administration.

Key Strengths

  • VLAN segmentation: Each department operates in its own VLAN, isolating traffic.
  • ACL enforcement: Extended ACLs on all seven sub-interfaces enforce inter-department rules.
  • AAA hardening: Administrative access is authenticated and audited.
  • Wireless security: WPA2-PSK secures departmental access points.
  • Least privilege: HR is isolated for compliance, Finance can reach only Project Management, Design cannot reach Finance, and IT retains administrative access.

Weaknesses

  • Single point of failure: The core router handles routing and firewall duties; a failure would disrupt most services.
  • Limited logging: No centralized logging or SIEM integration was configured.
  • Insecure management protocol: Telnet exposes credentials in plaintext.

Scalability and Future-Proofing

The design supports moderate growth but will hit limits due to IP exhaustion and the standalone core router.

Current utilization

  • Design VLAN has limited remaining capacity.
  • Conference VLAN is fully utilized.
  • Only 36 addresses remain from 192.168.10.220 onward.

Short-term growth

  • Supportable up to ~200–250 users by adding VLANs.

Long-term constraints (~300 users)

  • Router-on-a-stick becomes a bottleneck.
  • The /24 address space will be exhausted.

Future-proofing steps

  • Migrate to Layer 3 switching with SVIs for inter-VLAN routing.
  • Expand address space for larger subnets and flexibility.
  • Add a backup router for resiliency.
  • Consider a Zero Trust model for centralized policy enforcement.

Challenges and How I Addressed Them

  • ZPF limitation in Packet Tracer: ZPF rejected sub-interface zone membership. I placed all VLANs into a single internal zone and enforced inter-department controls with ACLs.
  • DHCP relay across VLANs: DHCP broadcasts initially failed. I added ip helper-address to all sub-interfaces to relay DHCP to the server.
