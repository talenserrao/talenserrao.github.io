ROP Exploit with Arbitrary Write to .bss and Reverse Shell via system()

Description: This repository contains a Return-Oriented Programming (ROP) exploit targeting a 64-bit Linux binary vulnerable to buffer overflow. The exploit performs an arbitrary write to the .bss section to inject a reverse shell command, which is then executed using system(). The goal is to gain a remote shell on the target system.

This repository contains an exploit for a 64-bit Linux binary vulnerable to a buffer overflow.
The exploit uses ROP (Return-Oriented Programming) to achieve a write-what-where primitive, injecting a reverse shell command into the .bss section and then calling system() to execute it.

The exploit is written in Python using the Pwntools library.

GitHub: https://github.com/Tempest2488/ROP-exploit-bss-reverse-shell

Contents

  • remote_solve.py – Exploit script (writes reverse shell to .bss and executes it)
  • target – Target binary (64-bit ELF)
  • remote_libc.so.6 – Remote libc used by the server

Vulnerability Summary

  • Binary: target
  • Architecture: x86_64
  • Protections: NX enabled, no PIE, no stack canary
  • Vulnerability: Classic buffer overflow with arbitrary memory write
  • Technique:
    • Use ROP chain to write a reverse shell command into .bss memory
    • Call system() on that command
    • Use exit() to gracefully terminate (optional)

Requirements

  • Python 3.6+
  • Pwntools: 
    pip install pwntools
  • Ngrok: Used to create a TCP tunnel from the remote machine back to your local listener
    To run Ngrok for this exploit, use: 
    ngrok tcp 4444

Notes

  • The payload uses custom ROP gadgets to write arbitrary data into memory.
  • This technique avoids relying on already present command strings in memory.
  • Also, the code will print out important base addresses of functions such as:
    • offset
    • system
    • bin_sh
    • libc base address

Initially, I attempted to use the generic SSH client approach to execute the exploit remotely.
However, I wasn’t able to get a reverse shell this way.
Instead, I successfully established a reverse shell by creating a TCP tunnel using Ngrok to expose port 4444 on my local machine.

Demonstration

  • First, make sure you have the correct Libc since if the machine turns off or restarts, then the libc base address will change due to ASLR. So you have to go through the whole phase 2 again to find the libc base address. You have to add the base address here in the code.
  • Don’t save the file yet in the terminal and run ngrok tcp 4444
  • Once you run the code, you will be able to see this.
  • Take the username and port given in ngrok; in this case, I highlighted and then put in the code in the username and port sections, respectively
  • Once this part is done, save the file and run it. It will pack the payload into a file called payload.txt.
  • Then, run a netcat listener to be able to receive the reverse shell. The command is nc -lnvp 4444
  • Once the listener is running, take the payload.txt and upload it to the upload solutions on the webpage
  • Once you submit, you see a message saying BAD. Go to the terminal where your netcat is listening for incoming connections. You will see that I have caught the connection
